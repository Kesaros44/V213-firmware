======================================================================
 KRSplit V213 - 빌드 방법 & Vial 사용법 (2026-08-30 기준)
======================================================================

이 폴더에는 두 가지 버전이 공존합니다.

  keymaps/default  -> 순정 QMK 버전 (VIA/Vial 없음)
  keymaps/vial      -> Vial 지원 버전 (키맵/매크로를 GUI에서 편집 가능)

두 버전은 서로 다른 QMK 소스로 빌드해야 합니다.
  - 순정 버전  : mainline QMK  (https://github.com/qmk/qmk_firmware)
  - Vial 버전  : vial-qmk 포크 (https://github.com/vial-kb/vial-qmk)

이미 컴파일된 결과물도 폴더에 들어있으니, 새로 빌드할 필요 없이
바로 플래시만 하고 싶다면 "3. 플래시 방법"으로 건너뛰어도 됩니다.
  - krsplit_default.hex    (순정 버전, 기존 파일)
  - krsplit_v213_vial.hex  (Vial 버전, 2026-08-30 빌드)


----------------------------------------------------------------------
1. 순정(default) 버전 빌드 명령어
----------------------------------------------------------------------

# 1) mainline QMK 클론 (V213 폴더와 겹치지 않는 별도 위치에)
git clone --depth 1 https://github.com/qmk/qmk_firmware.git
cd qmk_firmware
git submodule update --init --depth 1 lib/lufa lib/printf

# 2) 파이썬 빌드 도구 설치 (최초 1회, 가상환경 권장)
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install qmk
qmk config user.qmk_home="$(pwd)"

# 3) 이 폴더(V213)의 파일들을 QMK 트리 안으로 복사
mkdir -p keyboards/krsplit/v213/keymaps/default
cp /경로/V213/config.h        keyboards/krsplit/v213/
cp /경로/V213/keyboard.json   keyboards/krsplit/v213/
cp /경로/V213/krsplit.c       keyboards/krsplit/v213/
cp /경로/V213/krsplit.h       keyboards/krsplit/v213/
cp /경로/V213/rules.mk        keyboards/krsplit/v213/
cp /경로/V213/keymaps/default/keymap.c  keyboards/krsplit/v213/keymaps/default/

# 4) 컴파일
make krsplit/v213:default

# 결과물: qmk_firmware/krsplit_v213_default.hex (또는 .build/ 안에도 생성됨)


----------------------------------------------------------------------
2. Vial 버전 빌드 명령어
----------------------------------------------------------------------

# 1) vial-qmk 클론 (mainline qmk_firmware와는 별도 폴더에! 중첩 금지)
git clone --depth 1 https://github.com/vial-kb/vial-qmk.git
cd vial-qmk
git submodule update --init --depth 1 lib/lufa lib/printf lib/chibios lib/chibios-contrib lib/vusb

# 2) 파이썬 빌드 도구 설치 (mainline과 별도로 다시)
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install qmk
qmk config user.qmk_home="$(pwd)"

# 3) 이 폴더(V213)의 파일들을 vial-qmk 트리 안으로 복사
mkdir -p keyboards/krsplit/v213/keymaps/vial
cp /경로/V213/config.h        keyboards/krsplit/v213/
cp /경로/V213/keyboard.json   keyboards/krsplit/v213/
cp /경로/V213/krsplit.c       keyboards/krsplit/v213/
cp /경로/V213/krsplit.h       keyboards/krsplit/v213/
cp /경로/V213/rules.mk        keyboards/krsplit/v213/
cp /경로/V213/keymaps/vial/*  keyboards/krsplit/v213/keymaps/vial/

# 4) 컴파일 (기본 keymap 폴더 이름은 반드시 "vial"이어야 함)
make krsplit/v213:vial

# 결과물: vial-qmk/krsplit_v213_vial.hex


----------------------------------------------------------------------
3. 플래시 방법 (QMK Toolbox, 양쪽 공통)
----------------------------------------------------------------------

이 보드는 SPLIT_HAND_PIN으로 좌/우를 하드웨어에서 자동 판별하므로,
같은 hex 파일 하나를 양쪽 보드에 각각 구우면 됩니다. (좌우용 hex 따로 없음)

  1. 왼쪽 보드만 USB로 연결
  2. Fn 레이어(_WMFN1)의 좌상단 또는 우상단 QK_RBT 키를 눌러 부트로더 진입
     (또는 보드에 리셋 버튼이 있다면 그걸로)
  3. QMK Toolbox에서 원하는 hex 파일 선택 (krsplit_default.hex 또는 krsplit_v213_vial.hex)
  4. Auto-Flash 켜두면 부트로더 진입 즉시 자동으로 플래시됨 (atmel-dfu 방식)
  5. USB 케이블을 빼고 오른쪽 보드로 교체 연결
  6. 2~4번 반복 (동일한 hex 파일로)
  7. 양쪽 다 끝나면 정상적으로 케이블 연결해서 동작 확인

주의: 한 번에 한쪽씩! 양쪽을 동시에 USB로 연결해서 플래시하는 방식이 아닙니다.


----------------------------------------------------------------------
4. Vial 사용법 (krsplit_v213_vial.hex를 양쪽에 플래시한 뒤)
----------------------------------------------------------------------

1) Vial 앱 다운로드: https://get.vial.today (또는 vial.rocks)

2) 앱 실행 후 키보드 연결하면 자동 인식됨.
   - 이 펌웨어는 VIAL_INSECURE 모드로 빌드되어 있어서
     별도의 "언락 콤보"(특정 키 조합) 없이 바로 편집 가능함.
   - 보안이 필요하면 keymaps/vial/rules.mk에서 VIAL_INSECURE 줄을 지우고
     config.h에 VIAL_UNLOCK_COMBO_ROWS / VIAL_UNLOCK_COMBO_COLS를 추가해서
     재빌드하면 됨.

3) 편집 가능한 항목
   - Keymap 탭: 레이어 0(Windows 베이스), 1(Mac 베이스), 2(Fn) 키 리매핑
   - Encoders 탭: 우측 로터리 엔코더 CW/CCW 동작 변경
   - Macros 탭: 매크로 녹화/편집 가능

4) 편집 불가능한 항목 (의도적으로 비활성화됨)
   - Tap Dance, Combo, Key Override 탭은 회색으로 비활성화되어 있거나 안 보일 수 있음
     -> rules.mk에서 TAP_DANCE_ENABLE/COMBO_ENABLE/KEY_OVERRIDE_ENABLE을 no로 꺼둔 상태.
        atmega32u4의 1KB EEPROM이 부족해서 매크로 공간을 확보하려고 끈 것.
   - 4번째(빈 예비) 레이어도 Vial 빌드에서는 제외됨 (원래도 안 쓰이던 레이어)

5) 메모리 한계 (중요, 넘으면 저장이 안 될 수 있음)
   - EEPROM 1024바이트 중 매크로 편집용으로 남은 공간은 약 139바이트뿐임.
   - 여러 개의 긴 매크로를 한꺼번에 만들면 용량 초과로 저장이 안 될 수 있음.
   - 짧은 단축 문구 몇 개 정도가 현실적인 한계.

6) 백업
   - Vial 앱 메뉴에서 "Export Keymap"으로 현재 키맵 설정을 JSON으로 저장해두면
     펌웨어를 다시 플래시하거나 다른 보드로 옮길 때 "Import Keymap"으로 복원 가능.


----------------------------------------------------------------------
5. 참고: 메모리 예산 상세 (atmega32u4: 플래시 32KB / EEPROM 1KB)
----------------------------------------------------------------------

플래시(프로그램 메모리, 부트로더 제외 28672바이트 실사용):
  - Vial 버전: 27824 / 28672 바이트 (97%, 여유 848바이트)
    -> 마우스키(MOUSEKEY_ENABLE) 기능을 꺼서 겨우 맞춘 상태.
  - 순정 버전: 여유 있음 (약 65% 사용, 자세한 수치는 최초 분석 참고)

EEPROM (1024바이트 전부 사용, Vial 버전 기준):
  - EECONFIG/VIA 기본 설정 영역     : 41 바이트
  - 다이나믹 키맵 (3레이어x132칸x2B) : 792 바이트
  - 엔코더 저장 (1개x3레이어x4B)     : 12 바이트
  - QMK 설정 동기화 블록            : 40 바이트
  - 탭댄스/콤보/키오버라이드/리핏키  : 0 바이트 (비활성화)
  - Vial 매크로 편집 버퍼 (남는 공간): 139 바이트
  ------------------------------------------------
  합계                              : 1024 바이트 (딱 맞춤)

나중에 NKRO나 다른 기능을 추가하고 싶으면, 이 예산 표를 다시 계산해서
어딘가는 더 줄여야 공간이 나옵니다. 여유가 거의 없는 상태라는 점 참고.
